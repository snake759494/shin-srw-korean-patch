# v1.0.9 — 열린 이슈 #87~#107 전수 재검수 및 후속 패치

v1.0.9는 초반 플레이에서 발견된 문장 제보를 해당 화면의 문자열 하나만 바꾸는
방식으로 처리하지 않고, 원본 디스크에서 다시 추출한 전체 시나리오·전투 대사와
실행 파일의 고정 문자열 풀을 함께 대조한 릴리스입니다. 같은 일본어 레코드가
여러 시나리오에 복제된 경우에는 모든 복제본을 같은 한국어로 맞췄습니다.

이번 릴리스의 소스 기준은 다음과 같습니다.

- SCEDATA: 128개 멤버, 시나리오 대사 8,427개 레코드
- BTTMES: 158개 뱅크, 전투 대사 5,355개 레코드
- 실행 파일 문자열 풀: 파일럿명·기체명·무기명·시스템·정신 커맨드·지형 값
- 폰트: 12×12 본문 글리프와 전투 파일럿명 전용 8×16 코드 페이지
- 백과사전: 파일럿 347개, 로봇 242개 번역 레코드

## 이슈별 반영 내용

### #87 — 브라이트 전투 대사

원문과 전투 대사 뱅크를 다시 매칭해 브라이트의 전투 명령을 고쳤습니다.

- `BTT-03-10-001A74`: `탄막이 얇다!! 뭘 하고 있어!!` → `탄막이 얇다!! 뭘 하고 있나!!`
- `BTT-03-1E-001B73`: 중간에서 끊기던 `뭘 하고\n 있어!?` → `뭘 하고 있나!?`
- `BTT-03-19-001B0B`: `그렇게 두지 않는다!!` → `그렇게 두지 않겠다!!`
- `SCE-058-0118`: `철수신호를`을 `철수 신호를`로 분리하고 문장 부호와 명령형을 정리했습니다.

### #88 — 코우지·보스보로트 대사

`SCE-058-0111`~`SCE-058-0117`의 대화 순서와 말투를 원문·첨부 화면과 대조했습니다.
코우지의 반응, 보스의 허세 섞인 말투, 누케의 사과 대사가 서로 다른 화자로
합쳐지거나 존댓말로 바뀌지 않도록 각각 독립 레코드에 넣었습니다.

- `엉터리라니, 뭐가 엉터리냐! / 열받는군!`
- `그렇지. / 낡긴 했어도.. 응? / 누케! 어디가 낡았다는 거냐!`
- `힝-, / 보, 보스, 미, 미안해요`

### #89 — SRX 팀 및 후반부 연결 대사

`SCE-058-0057`~`SCE-058-0128` 중 제보된 레코드를 전부 다시 배치했습니다.
대표적으로 `류세이, 너 여기까지 어떻게 온 거냐?`, `아무렇지 않게 말하는군,
라이`, `엄청난 거짓말쟁이는 아니잖아`, `소개 같은 건 필요 없어`, `어랏,
화내고 가 버렸네`, `배속되었습니다`, `진 겟타!? ... 봉인을 푼 겁니까?`의
줄바꿈·띄어쓰기·화자 연결을 고쳤습니다.

샤크티 구출 장면도 함께 수정했습니다.

- `SCE-058-0086`~`SCE-058-0099`: 샤크티·루페 시노 대사, `가까워졌을 때`,
  `울지 마`, `이제 와서 데려오는 건 무리다`, `웃소 군`, `가기는커녕`을 정리
- `SCE-058-0121`, `SCE-058-0124`, `SCE-058-0127`, `SCE-058-0128`:
  코우지에게 마징가Z 파츠를 전달하고 정비사를 부르는 대화의 문장 단위 수정
- `류마`로 섞여 있던 나가레 료마 표기를 전체 번역 데이터에서 `료마`로 통일
  (`류세이`는 그대로 유지)

### #90 — 상태창 지형·실드 값

이 항목은 일반 대사 JSON이 아니라 실행 파일의 동적 상태창 경로를 사용합니다.
기존 상태창 패치가 실제 v1.0.9 이미지에도 남아 있는지 다음을 직접 검사했습니다.

- 고정 라벨 `地形` 9개 이상을 `지형`으로 유지
- 실행 파일 `0x70300`의 인라인 `無/有` 값을 `없/있`으로 유지
- 시스템 풀 `0x702BC`의 `陸/宇/空`을 `육/우/공`으로 유지
- 두 줄 지형 보정 문구의 링 버퍼 길이 패치(`0x0B6304`, `0x0B631C`) 유지

따라서 화면에서 한자가 다시 나오거나 `없/있` 값이 어긋나는 경로가 재발하지
않도록 고정 오프셋 QA를 추가했습니다.

긴 문단에는 원문의 `WAIT` 경계를 유지했으며, SCEDATA 재압축 후 모든 멤버의
버퍼 여유와 레코드 종료 위치를 다시 검사했습니다.

## #107 — easy-apply 패키지 해시 불일치

v1.0.9 easy-apply ZIP에 포함된 `apply.ps1`이 v1.0.8의 결과·패치 해시를
참조하고 있어, 정상적인 v1.0.9 xdelta를 `[1/5] 패치 파일 검증` 단계에서
손상된 파일로 오인하는 패키징 오류를 확인했습니다. 패치 생성기에도 다음
검사를 추가했습니다.

- ZIP을 만들기 전에 버전·원본 Track 1·결과 Track 1·Track 2 해시를 스크립트와 대조
- xdelta 생성 후 계산한 패치 해시를 ZIP 내부 `apply.ps1`에 자동 주입
- `SHA256SUMS_v1.0.9.txt`에 xdelta뿐 아니라 easy-apply ZIP 해시도 기록
- 새 xdelta를 원본에 역적용해 Track 1 SHA-256 `3164ef…`와 일치하는지 재확인

기존 v1.0.9 easy-apply 자산은 잘못된 스크립트가 들어간 파일이므로 교체했고,
새 ZIP의 `EXP_PATCH`는 `8cc7382b…`로 실제 포함 패치와 일치합니다. 이슈 댓글에
원인·확인 방법·새 자산 해시를 남겼습니다.
