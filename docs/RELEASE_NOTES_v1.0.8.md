# v1.0.8 — #74 전투 대사창·전투 상태 무결성 수정

v1.0.8은 [#74](https://github.com/snake7594/shin-srw-korean-patch/issues/74)의 전투 중 대사창 겹침과 공격 표적 오지정 제보를 대상으로 만든 후속 패치입니다. 제보 본문뿐 아니라 추가 댓글 2개와 첨부된 DuckStation 설정 화면·전투 화면을 모두 확인했습니다. 첫 번째 화면은 파일럿 이름이 인물 사진 영역 앞으로 밀려 나오는 현상이고, 두 번째 화면은 대사 표시 직후 전투 상태가 기대한 유닛이 아닌 다른 표적을 가리키는 현상입니다.

제보자의 추가 설정 화면은 Steam Deck의 기본 DuckStation 설정(일반적인 Vulkan·CPU 리컴파일러·16:9 렌더링·기본 속도)으로 보였고, 다른 일본판에서 v0.9를 적용했을 때는 문제가 없었다는 설명도 있었습니다. 따라서 이번 수정은 화면비나 에뮬레이터 옵션을 전제로 하지 않고, 번역 이미지 안에서 대사 렌더러와 전투 데이터가 소비하는 포인터·테이블·폭 규칙을 원본과 대조하는 방식으로 진행했습니다.

## 원인 분석

### 1. 파일럿 이름과 일반 대사의 글자 폭이 달랐습니다

전투 대사에서 `FC09`는 실행 파일의 `PILOTNAME` 풀을 읽고, 이어서 인물 사진과 대사 본문을 전투 창에 배치합니다. 일본판의 파일럿 이름은 전투용 8×16 반각 셀을 기준으로 출력됩니다. 기존 한글화 빌드는 일반 대사와 같은 16×16 한글 글리프(`F0`~`F5` 2바이트)를 파일럿 이름에도 사용했습니다.

그 결과 한글 한 글자가 원본의 1셀 대신 1.5셀 폭으로 계산되었습니다. 예를 들어 첫 전투의 `아무로`는 원본의 3셀 이름이어야 하지만, 이전 방식에서는 각 음절이 넓은 글리프로 출력되어 이름 줄이 초상 영역까지 침범했습니다. 이 현상은 단순히 4:3·16:9 화면비를 바꾸어 해결되는 문제가 아니었습니다.

### 2. 사용하지 않는 이름 풀 슬롯이 다음 테이블을 문자열로 읽을 수 있었습니다

실행 파일의 `PILOTNAME`과 `PILOTFULL`에는 실제 문자열이 없는 예약 슬롯이 각각 152개 있습니다. 일부 슬롯은 다음 테이블 앞의 패딩을 가리키는데, 기존 점검기는 파일 전체에서 다음 `FF`를 찾았습니다. 이 방식은 테이블 경계를 넘어서 다음 테이블의 스텁과 후속 데이터를 하나의 문자열로 오인할 수 있습니다.

문자열 풀을 재배치하는 과정에서 이런 가짜 문자열을 실제 이름으로 취급하면 이름·초상 조회 영역이 변하고, 이후 전투 초기화가 참조하는 실행 파일 영역까지 오염될 수 있습니다. v1.0.8은 각 풀의 arena 경계를 넘는 읽기를 금지하고, 실제 문자열이 아닌 304개 슬롯을 공용 종료 레코드 `FF`로 격리했습니다. 살아 있는 이름·초상 인덱스와 테이블을 임의로 재번호화하지는 않았습니다.

### 3. BTTMES의 특수 교차 뱅크 인덱스를 구분하지 않았습니다

BTTMES에는 대부분의 뱅크처럼 자기 뱅크 안의 메시지를 가리키는 인덱스와, 특수 뱅크에서 다른 뱅크를 가리키는 인덱스가 함께 존재합니다. 특수 뱅크 전체를 일반 로컬 인덱스로 처리하면 메시지 본문이 커져 뱅크 위치가 이동할 때 교차 참조가 낡은 위치를 남길 수 있습니다.

v1.0.8은 유효한 교차 뱅크 참조 3개만 새 위치로 이동시키고, 원본의 더미·로컬 값 10개는 바이트 그대로 보존합니다. 동시에 SCEDATA·BTTMES 인덱스의 실행 파일 미러도 새 위치를 반영했습니다.

## 적용한 수정

- `PILOTNAME` 전용 8×16 코드 페이지를 추가했습니다. 일반 대사·메뉴·전투 본문은 기존 16×16 한글 코드 페이지를 계속 사용합니다.
- 파일럿 이름에 실제로 필요한 compact 글리프 20개와 기존 소형 글리프 `아` 1개를 8×16 타일로 삽입했습니다.
- 첫 전투의 `아무로`는 `ED 42 49 FF`로 저장되며, 렌더러 기준 전진 폭은 6(3셀)입니다. 인물 사진 앞에 이름이 겹치지 않도록 원본 일본어 이름과 같은 셀 폭을 유지합니다.
- 풀별 문자열 읽기에 arena 상한을 적용했습니다. 종료 바이트가 다음 테이블에 있을 때는 유효한 문자열로 인정하지 않습니다.
- `PILOTNAME` 예약 슬롯 152개와 `PILOTFULL` 예약 슬롯 152개를 공용 빈 레코드 `FF`로 격리했습니다.
- 파일럿 풀의 announcing stub, 얼굴 테이블, 첫 전투용 고정 데이터는 원본 바이트를 유지했습니다.
- BTTMES 158개 뱅크와 160개 인덱스 엔트리를 다시 생성하고, 특수 교차 뱅크의 유효 참조 3개만 재배치했습니다.
- BTTMES 스크립트 점프 피연산자와 메시지 그래프를 함께 검사해 이동된 메시지로 연결되도록 했습니다.
- 독립 점검 도구 `tools/qa_issue74.py`와 `tools/audit_scedata_event_refs.py`를 추가했습니다. 이 도구들은 에뮬레이터를 실행하지 않고 풀 경계, 첫 전투 파일, BTT 그래프, SCEDATA 버퍼 여유를 검사합니다.
