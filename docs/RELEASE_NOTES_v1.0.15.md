## 9화 등 작전목적의 승리·패배조건이 비어 보이던 문제 (#12)

빌더 버그였습니다. 맵 도중 목표가 바뀌는 시나리오는 이벤트 플래그에 따라 작전목적 블록을
고르는 조건 분기 스크립트(`76 … 78 … 77 … 78 … 75`)를 씁니다. 빌더는 단순한 형태
(`78 … 75`)만 새 위치로 옮겨 주고 있어서, 번역문이 길어지면 이 분기 스크립트가 한국어 대사
한가운데를 가리켰습니다. 그래서 승리·패배조건이 모두 공백으로 나왔습니다.

- 분기 스크립트의 모든 블록 참조를 따라가 다시 맞추도록 고쳤습니다. 해당 시나리오 멤버는
  20, 25, 29, 34, **41(9화)**, 43, 45, 67입니다.
- 승리조건 목록이 길어지면 패배조건 목록의 위치가 밀리는데, 블록의 패배조건 오프셋은 갱신하지
  않고 있었습니다. 이것도 함께 고쳤습니다(42, 45, 46, 64, 72 등).
- 완성 이미지의 128개 멤버 전부에서 각 블록이 승리·패배 목록의 시작을 정확히 가리키는지
  검사했습니다.

## 대사 글자 밀림 (#4)

대사 창은 한 줄에 20칸이 들어가고 21칸째부터는 다음 줄로 넘어갑니다. 한글, 영문, 숫자, 문장부호,
공백 모두 1칸입니다. 전체 대사를 검사해 20칸을 넘는 줄이 있던 시나리오·전투 대사 133개를 모두
다시 나눴습니다. 화자 이름이 따로 한 줄을 쓰는 프롤로그는 창이 달라 제외했습니다. 원문보다 줄이 늘지 않게 했고, 맞지 않는 대사는 문장을 다듬었습니다.

함께 고친 표현:

- 아렌비(アレンビー) 표기 통일: 대사·이름·도감·시나리오 제목까지 전부
- 「포오오렬」 → 「폭오오렬」 (폭열 갓 핑거 24곳)
- 「하잖 나」「소행성 에」「존재한다, 는」「취하 겠다」 등 띄어쓰기
- 「대체 전체」 → 「대체 저게」, 「슈○치」 → 「슈왓치」, 쿄우지 「글렀다」 → 「틀렸다」
- 「가 주게」 → 「가주게」로 통일

## 도감 글자 밀림·뒷부분 잘림 (#7, #8)

도감 창은 한 줄 25칸이고 자동 줄바꿈이 없어, 넘치는 글자는 창 밖으로 그려져 잘렸습니다.
25칸을 넘던 로봇 도감 27개, 파일럿 도감 13개의 줄을 다시 나눴습니다.

- 「다이세츠잔 오로시」·「대설산 던지기」 → 「대설산 오로시 2단 뒤집기」로 통일 (도감, 전투 대사, 무기명)
- 옵션의 「デモ選択」 머리글 → 「데모」

## UI (#9, #10, #11)

- 부대표 정렬 「HP쉽」「EXP쉽」 → 「HP순」「EXP순」. 順 글자 칸 하나가 번역되지 않고 남아 있었습니다.
- 버튼 설정 「스타」「셀렉」 잘림 → 「시작」「선택」. 칸이 반각 4칸이라 두 글자만 들어갑니다.
- **LV의 V 글꼴**: 인코더가 V를 볼테스Ⅴ용 로마 숫자 칸으로 찍고 있었습니다. LV뿐 아니라
  대사의 TV, V-MAX, V2 등도 마찬가지였습니다. 이제 볼테스Ⅴ만 로마 숫자를 쓰고 나머지는
  일반 V를 씁니다.
- 강화파츠 장착 설명을 메뉴 표기와 같은 「강화품」으로 맞췄습니다. 메뉴 칸에는 「강화파츠」가
  들어가지 않습니다.

## 빌드·검사 도구

- `qa_translation.py`가 대사 20칸, 전투창 2줄, 도감 25칸을 검사합니다. 같은 문제가 다시
  들어오면 빌드 전에 걸립니다.
- 전투 대사 파일의 메시지 탐색이 스크립트 영역의 표 값 `0x08FC`를 메시지 시작으로 오인할 수
  있던 문제를 빌더와 감사 도구에서 함께 고쳤습니다.
